Open tools for closed systems.

Fieldmouse Works builds open-source software for ecosystems that are expensive, restrictive, difficult to leave, or designed around permanent vendor dependence. The goal is practical: you should be able to run the software, understand it, move your data, and keep operating on your own terms.

Conary

A cross-distro Linux package manager written in Rust for RPM, DEB, Arch, and native CCS packages on Fedora, Ubuntu, and Arch. It preserves each source format's lifecycle semantics without delegating normal operations to the host package manager.

Content-addressed storage, recorded changesets, and immutable system generations make package state and recovery explicit. The workspace also includes Remi, Conary's package-conversion and signed-catalog service.

Public package-feed readiness and external testing are tracked in the launch status, separately from the ability to build or run the client.

Pre-alpha preview: use a VM or disposable host. Not a production replacement for apt, dnf, or pacman. Read the current status before testing.

Consolebook

Rust
License
AGPL-3.0-only

pre-alpha

Self-hosted training-record software for emergency communications centers: versioned programs, Daily Observation Reports, weekly summaries, task signoffs, and trainee histories, with agency-owned data and portable records.

Implemented workflows include assignment-scoped access, immutable finalized records, acknowledgments, amendments, verifiable structured exports, and complete trainee packets.

Rust and Axum, SQLite, and an embedded SvelteKit interface: one executable and one data directory per installation. A small center should be able to operate its own system without a collection of external services.

Pre-alpha: usable for development and evaluation only. Use invented data, never production or personnel records. Retention, holds, lawful disposition, attachments, PDF rendering, and stronger restore proof remain on the roadmap.

About the name

Fieldmouse Works is named for the small creature willing to take on something much larger than itself. That is a useful model for the work here: find the closed system, understand what it actually does, and build the open door.

Built by Peter Permenter, a systems and backend engineer focused on explicit state, reproducible behavior, recovery, portability, and software that stays operable without a permanent vendor relationship.
